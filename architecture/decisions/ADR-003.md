# ADR-003: Hand off checked artifacts, not conversations; the issue text stops at the spec

**Date:** 2026-11-24 · **Status:** Accepted · **Decision area:** D3 Hand-offs

## Context
Each agent starts with an empty context. What we put in decides what it can do and what it can be
tricked into. The issue text is the only untrusted input (ADR-009). Full transcripts are long and
contain reasoning that later agents would treat as fact.

## Decision
| To | Receives | Deliberately left out |
|---|---|---|
| Spec | issue title and body (wrapped as untrusted data), `README.rst`, A1 skill | code |
| Design | the spec's acceptance criteria (machine-readable block) and summary, `ARCHITECTURE.md`, repo | raw issue text, spec register |
| Coder | ACs, `design.md`; on retries the failing pytest output (truncated) and, if any, the reviewer's findings | tester's conversation, raw issue text |
| Tester | ACs, repo with the change applied, list of changed files | coder's conversation, `design.md` |
| Reviewer | issue text, `git diff main...HEAD`, repo at PR head | spec, design, test report, transcripts, PR description |

Each artifact has a fixed machine-readable block (JSON in a fenced code block) that the next
stage's check parses; the prose around it is for humans.

## Alternatives considered
- **Pass full transcripts forward.** Most information, but the issue text and every tool output
  travel to every agent, contexts grow, and later agents inherit earlier mistakes as facts.
- **Pass LLM-written summaries.** Short, but a summary is a new unchecked claim.
- **Give the tester the design.** It would test the plan, not the requirement; we want tests that
  catch a wrong plan.

## Consequences
- An injected instruction in the issue has to survive the spec agent's rewriting into acceptance
  criteria before it reaches an agent with write access.
- The spec must be good enough to stand alone; a weak spec propagates (a known risk: the coder never
  sees the issue).
