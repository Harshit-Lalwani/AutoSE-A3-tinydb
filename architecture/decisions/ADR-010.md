# ADR-010: Label or slash command from users with write access; one run per issue at a time

**Date:** 2026-11-24 · **Status:** Accepted · **Decision area:** D10 Triggers

## Context
Two maintainer gestures should start the workflow: adding a label, or commenting a command. Labels
can only be added by users with triage access or more, but comments can be posted by anyone.
Two runs on the same issue would race on the same branch and PR.

## Decision
- `issues: labeled` with label `autose` → full pipeline (label `autose-single` → experiment variant).
- `issue_comment: created` with a body starting `/autose` → full pipeline on an issue, review only on
  a pull request (`/autose review`).
- The gate job asks the API for the actor's permission (`gh api …/collaborators/<actor>/permission`)
  and continues only for `admin`, `maintain` or `write`. Bots are ignored.
- `concurrency: autose-<issue or PR number>-<variant>` with `cancel-in-progress: false`: a second
  trigger waits for the first to finish instead of racing it. Different issues run in parallel.

## Alternatives considered
- **Label only.** Safe by construction, but no way to ask for a review on an existing PR.
- **`cancel-in-progress: true`.** The newest request wins, but a cancelled run may leave a
  half-pushed branch.
- **Trigger on every new issue.** Spends money on spam and on issues nobody has triaged.

## Consequences
- A maintainer can retrigger by removing and re-adding the label.
- The workflow is defined in `main`; issue and comment events always run the version on the default
  branch, so a PR cannot change the workflow that reviews it.
