# ADR-007: Deterministic checks decide every hand-off; LLMs only produce

**Date:** 2026-11-24 · **Status:** Superseded by [ADR-013](ADR-013.md) · **Decision area:** D7 Checks

## Context
Each stage has a check. An LLM judging another LLM's output is cheap to build but is a second
opinion that can be wrong in the same way, and it costs a call per check. Most of the checks the
assignment asks for can be reduced to something code can verify.

## Decision
| Stage | Check (in `checks.py`) |
|---|---|
| 1 | every AC in the JSON block has Given/When/Then, no `TBD`, no vague word (fast, easy, properly, …); no `Blocking` question |
| 2 | named files exist (or `new: true`); every named function/class appears in its file (`def`/`class` grep) |
| 3 | diff non-empty; `compileall`, `import tinydb`, `mypy tinydb` pass |
| 4 | a `test_ac<k>_*` test exists for every AC; full suite green; ≥1 new test fails on `main` |
| 5 | PR open; dispatched CI run on the PR head concludes `success` |
| 6 | reviewer verdict is valid JSON; `approve` only counts if the reviewer actually ran a command (from the tool log) |

The final pass/fail is always made by `checks.py`. The reviewer's verdict is the only LLM judgement
in the loop, and it is validated by code.

## Alternatives considered
- **LLM judge per stage.** Can judge "is this AC testable?" more flexibly, but doubles the calls and
  the judge can be talked into a pass.
- **No stage checks, only the final tests.** Cheaper, but errors are found late, after the most
  expensive stages.

## Consequences
- Checks are strict on form and weaker on meaning: a well-formed but wrong AC passes stage 1. The
  hidden tests and the reviewer are what catch wrong meaning.
- "≥1 new test fails on main" catches vacuous tests; it would wrongly reject a pure refactor issue
  (none of our issues is one).
