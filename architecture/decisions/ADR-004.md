# ADR-004: State in Actions artifacts + the branch; runs are restartable from the start

**Date:** 2026-11-24 · **Status:** Accepted · **Decision area:** D4 State

## Context
State crosses three boundaries: stage → stage (same job), job → job (stages → review → fix, fresh
runners), and run → run (a maintainer triggers again). The reviewer must not see the earlier
artifacts, so they cannot live on the PR branch.

## Decision
- **Code** lives on the branch `autose/issue-<N>` (variant runs: `autose/issue-<N>-<variant>`).
- **Artifacts** (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`,
  `state.json`, agent transcripts) are uploaded as Actions artifacts after every stage; fix jobs
  download them. `state.json` holds the stage history, attempts, review round and token counts.
- **Between runs** nothing is reused: a new trigger resets the branch to `main` and starts at
  stage 1; an existing PR for the branch is updated instead of duplicated.
- The PR description (`pr.md`) and the posted review make the run readable without downloading
  anything.

## Alternatives considered
- **Commit artifacts to the branch** (e.g. `.autose/`). Visible and versioned, but then the
  reviewer's checkout contains the implementer's design and test report, breaking ADR-008, and the
  PR diff gets noisy.
- **PR comments as state.** Readable, but parsing comments back is fragile and anyone can comment.
- **Actions cache.** Evictable and keyed by content, not meant for run state.

## Consequences
- "Re-run failed jobs" works: earlier jobs' artifacts are still in the run, and fix jobs reset the
  branch to the last pushed head before continuing.
- Artifacts expire after the repository's retention period (90 days by default), enough for grading.
- A full restart costs a full set of model calls.
