# ADR-011: Nemotron-3 Ultra for the builders, MiniMax M3.1 Flash (thinking off) for the reviewer

**Date:** 2026-11-24 · **Status:** Accepted · **Supersedes:** [ADR-006](ADR-006.md) · **Decision area:** D6 Models

## Context
ADR-006 chose MiniMax M3.1 Flash for the four builder roles based on a one-token tool-call test
(1.8 s). The first local smoke run of stage 1 showed this was wrong: MiniMax M3.1 Flash is a
reasoning model and by default spent its whole 8,000-token budget on hidden reasoning and returned
**no content**, twice, so the spec check failed with "no parseable json block". We then measured
each candidate on the same 3-sentence question (NIM, 2026-11-24):

| Model | Setting | Time | Completion tokens | of which reasoning |
|---|---|---|---|---|
| MiniMax M3.1 Flash | default | 110.0 s | 2,778 | 2,641 |
| MiniMax M3.1 Flash | `reasoning_effort: low` | 238.2 s | 3,953 | 3,792 |
| MiniMax M3.1 Flash | thinking off (`chat_template_kwargs`) | 9.8 s | 80 | 0 |
| Nemotron-3 Ultra 550B | default | 6.3 s | 145 | 38 |
| Nemotron-3 Ultra 550B | thinking off | 12.5 s | 95 | 0 |
| Kimi K3.1 Pro, GLM-5.3 Flash | default and thinking off | no answer in 160 s | | |

An agent step that costs 2–4 minutes makes a 40-step coder run take hours, beyond our job timeout.

## Decision
| Role | Primary | Fallback |
|---|---|---|
| Spec, design, coder, tester | `nvidia/nemotron-3-ultra-550b-a55b` (NIM), default reasoning | same model `:free` on OpenRouter |
| Reviewer | `minimaxai/minimax-m3.1-flash` (NIM), thinking off | `google/gemma-4-31b-it:free` (OpenRouter) |

We keep the two-family split of ADR-006 (reviewer ≠ builders) but swap the roles: the larger model
with cheap, short reasoning does the work that most needs it (coding); the reviewer runs without
hidden reasoning but is forced to reason in the open by running commands (ADR-008).

## Alternatives considered
- **MiniMax with thinking off for the builders, Nemotron as reviewer** (ADR-006 swapped only in
  settings). Keeps "reviewer stronger than builder", but puts the weaker, non-reasoning setting on
  the hardest task (editing code); our pass rate depends most on the coder.
- **MiniMax with reasoning for the reviewer only.** About 2 minutes per step × ~15 steps per review
  is too slow and the hidden reasoning is not visible in the review.
- **Nemotron for everything.** Simplest and fastest, but loses model diversity, which ADR-008 relies on.

## Consequences
- Lesson recorded: a model check must measure a realistic call (long output, tool use), not a
  one-token ping.
- The reviewer's fallback (Gemma) is rate-limited on the free tier; if MiniMax is down the review
  may stop, and the run then ends with the PR open and no review (the human still decides).
