# ADR-012: A hard token budget is our spending limit

**Date:** 2026-11-24 · **Status:** Accepted · **Decision area:** D9 Safety and failures (cost), refines ADR-009

## Context
The rules ask for a hard spending limit with the model provider. All our models run on free tiers
(NIM free tier; an OpenRouter key without credits, so only `:free` models), so the money spent is
zero by construction, and the providers offer no dollar limit that would mean anything. What can
still run away is *usage*: rate limits, run time, and, if a paid model is ever configured, money.
ADR-009 capped steps per agent and tokens per agent, but not tokens per run, so a run with many
retries and two fix rounds had no single upper bound.

## Decision
Tokens are the spend proxy, enforced in code before every model call (`agent.charge_check`):
- **Per run:** 2,500,000 tokens for all builder agents of one run (stages job and both fix jobs share
  it; the amount used travels in `state.json`).
- **Per review:** 400,000 tokens.
- A call is refused if its worst case (prompt size estimate + `max_tokens`) would cross the limit,
  so the limit is never exceeded, not just detected afterwards. The refused stage writes
  `## Why this stage stopped` in its artifact, the run stops, and the issue gets a comment. A review
  that runs out of budget posts verdict `incomplete` and does not trigger a fix round.
- The limits live in `workflow/agent/models.json` (`budget`). Totals per run are reported in
  `results/results.csv`.

Calibration (local smoke run, one clean pass): spec 12k, design 178k, implement 132k, test 78k
tokens (≈400k); one review ≈185k. The caps allow roughly 5 such passes per run and 2 reviews' worth
per review.

## Alternatives considered
- **Dollar limit at the provider.** The natural choice with a paid key; meaningless for free tiers.
  If a paid model is added, set it there as well (e.g. OpenRouter per-key credit limit).
- **A project-wide token ledger across runs.** Needs persistent state that the `GITHUB_TOKEN` cannot
  write (repository variables need a PAT). Instead the project total is bounded by (caps × number of
  runs), and only users with write access can start runs (ADR-010).

## Consequences
- Every run has a known worst-case cost before it starts.
- The first five pipeline runs (issues #1–#5, started 15:00 UTC) ran before this ADR, with only the
  per-agent caps of ADR-009 (1.5M tokens and a step limit per agent); later runs use the run budget.
