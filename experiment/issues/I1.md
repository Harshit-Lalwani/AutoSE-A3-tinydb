# Failed update() leaves an in-memory database half-modified (JSON file is fine)

I use TinyDB with `MemoryStorage` in my unit tests and a JSON file in production, and they don't behave the same when an update fails.

```python
from tinydb import TinyDB, Query
from tinydb.storages import MemoryStorage
from tinydb.operations import delete

db = TinyDB(storage=MemoryStorage)
db.insert({'name': 'a', 'tmp': 1})
db.insert({'name': 'b'})

db.update(delete('tmp'))   # KeyError: 'tmp', because the 2nd document has no 'tmp'
print(db.all())            # [{'name': 'a'}, {'name': 'b'}]  <- the first document was changed anyway!
```

With a JSON file the same code raises the KeyError and the file is unchanged, which is what I'd expect: the update failed, so nothing should have happened.

Related: if I ran `db.search(Query().tmp.exists())` before the failing update, the same search afterwards still gives me the old cached answer, even though (with MemoryStorage) the data did change. I only see the real data after `db.clear_cache()`.

I'd expect an update (or remove / insert_multiple) that raises to leave the database exactly as it was, whatever the storage, and searches to always match the stored data.
